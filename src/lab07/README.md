# Лабораторная работа №7: CLI для управления инвентарём оружия

## 1. Цель работы

- Реализовать консольное интерактивное приложение (CLI) для управления коллекцией оружия
- Применить трёхслойную архитектуру (CLI → App → Models)
- Освоить паттерн «Стратегия» для сортировки и улучшения
- Реализовать сохранение и загрузку данных в формате JSON
- Применить собственные исключения для предметной области

**Оценка: 5** — реализованы все требования на 3, 4 и 5 баллов.

---

## 2. Структура проекта

### 2.1 Файлы проекта

| Файл | Назначение |
|------|-----------|
| `models.py` | Базовый класс `Weapon` |
| `base.py` | Подклассы `Firearms`, `Edged` |
| `validate.py` | Валидаторы атрибутов оружия |
| `collection.py` | Класс `Inventory` — хранение коллекции |
| `exceptions.py` | Собственные исключения (`DuplicateItemError`, `ItemNotFoundError`) |
| `strategies.py` | Стратегии сортировки, фильтры, фабрики функций |
| `storage.py` | Сохранение и загрузка данных в JSON |
| `app.py` | Бизнес-логика + фабричные методы создания оружия |
| `cli.py` | Консольный интерфейс (только ввод и вывод) |
| `main.py` | Точка входа, авто-загрузка при старте и сохранение при выходе |
| `weapons.json` | Файл с данными (создаётся автоматически) |

### 2.2 Трёхслойная архитектура

```
main.py
  └── cli.py        ← слой представления: меню, ввод, вывод
        └── app.py  ← слой бизнес-логики: операции + создание объектов
              └── collection.py / models.py / base.py / strategies.py / storage.py
```

Каждый слой отвечает только за свои обязанности. `cli.py` не создаёт объекты моделей напрямую — это делегировано в `app.py` через фабричные методы `create_weapon()`, `create_firearms()`, `create_edged()`.

## 3. Описание реализации

### 3.1 Слой моделей (models.py, base.py)

**Класс `Weapon`** — базовый класс с атрибутами: `_imia`, `_damage`, `_rare`, `_hardness`, `_effects`, `_tip`, `__kolichestvo`.

Методы:

| Метод | Описание |
|-------|---------|
| `attack()` | Наносит урон, уменьшает прочность на 1 |
| `repair()` | Восстанавливает прочность до 100 |
| `status` | Property: возвращает состояние оружия |
| `imia` | Property с setter для переименования |

**Класс `Firearms(Weapon)`** — огнестрельное оружие. Дополнительные атрибуты: `_caliber`, `_magazine_capacity`.

| Метод | Описание |
|-------|---------|
| `reload()` | Перезарядка магазина |
| `calculate_price()` | Цена с учётом калибра и магазина |
| `display_info()` | Краткая информация |

**Класс `Edged(Weapon)`** — холодное оружие. Дополнительные атрибуты: `_blade_length`, `_material`.

| Метод | Описание |
|-------|---------|
| `sharpen()` | Заточка клинка |
| `calculate_price()` | Цена с учётом длины клинка |
| `display_info()` | Краткая информация |

### 3.2 Слой коллекции (collection.py)

Класс `Inventory` хранит список оружия и предоставляет методы:

| Метод | Описание |
|-------|---------|
| `add(w)` | Добавляет оружие, проверяет дубликаты по имени |
| `remove(w)` | Удаляет оружие по объекту |
| `remove_at_index(index)` | Удаляет по индексу |
| `find_by_imia(imia)` | Поиск по названию |
| `get_broken()` | Возвращает список сломанного оружия (`hardness == 0`) |
| `sort_by_imia()` | Сортировка по имени |

### 3.3 Слой бизнес-логики (app.py)

Класс `WeaponApp` — посредник между CLI и коллекцией:

| Метод | Описание |
|-------|---------|
| `add_weapon(weapon)` | Добавить, выбросить `DuplicateItemError` при дубликате |
| `remove_weapon(name)` | Удалить по имени, выбросить `ItemNotFoundError` |
| `find_by_name(name)` | Найти по имени |
| `get_all_weapons()` | Получить все оружие |
| `sort_by_strategy(strategy)` | Сортировка по стратегии |
| `filter_by_predicate(predicate)` | Фильтрация по предикату |
| `get_broken_weapons()` | Сломанное оружие |
| `repair_weapon(name)` | Починить по имени |
| `upgrade_weapon(name, strategy)` | Улучшить по стратегии |
| `create_weapon(...)` | Фабричный метод: создать `Weapon` |
| `create_firearms(...)` | Фабричный метод: создать `Firearms` |
| `create_edged(...)` | Фабричный метод: создать `Edged` |

### 3.4 Паттерн «Стратегия» (strategies.py)

**Стратегии сортировки:**

| Функция | Описание |
|---------|---------|
| `by_name` | По имени (алфавитный порядок) |
| `by_damage` | По урону |
| `by_rarity` | По редкости (Легендарное > ... > Обычное) |
| `by_damage_then_name` | По урону, при равном — по имени |
| `by_price` | По вычисляемой цене |

**Фильтры:**

| Функция | Описание |
|---------|---------|
| `is_legendary` | Только легендарное |
| `is_high_damage(w, min)` | Урон выше порога |
| `is_repairable` | Прочность < 100 |
| `is_firearms` | Только огнестрельное |
| `is_edged` | Только холодное |
| `make_damage_filter(min, max)` | Фабрика: фильтр по диапазону урона |
| `make_rarity_filter(rare)` | Фабрика: фильтр по редкости |

**Стратегии улучшения (callable-объекты):**

| Класс | Описание |
|-------|---------|
| `DamageUpgradeStrategy(bonus)` | Повышает урон на `bonus` |
| `RarityUpgradeStrategy` | Повышает редкость на один уровень |
| `RepairStrategy` | Восстанавливает прочность до 100 |

### 3.5 Собственные исключения (exceptions.py)

| Исключение | Когда выбрасывается |
|-----------|-------------------|
| `ItemNotFoundError` | Оружие не найдено в коллекции |
| `DuplicateItemError` | Оружие с таким именем уже существует |
| `InvalidWeaponDataError` | Некорректные данные при создании |
| `CollectionError` | Ошибка при работе с коллекцией |

## 4. Описание CLI

### 4.1 Главное меню

```
                     ИНВЕНТАРЬ ОРУЖИЯ
1.Добавить оружие
2.Показать всё оружие
3.Найти оружие по названию
4.Удалить оружие
5.Сортировка (стратегии)
6.Фильтрация
7.Показать сломанное оружие
8.Починить оружие
9.Улучшить оружие
0.Выход и сохранение
```

### 4.2 Обработка ошибок ввода

| Ситуация | Сообщение |
|----------|----------|
| Строка вместо числа | `Ошибка: введите число` |
| Число вне диапазона 0–9 | `Неверный пункт меню. Выберите 0-9.` |
| Пустое название | `Ошибка: название не может быть пустым` |
| Дубликат имени | `Ошибка: Оружие с именем '...' уже существует!` |
| Прочность не 0–100 | Перехватывается валидатором |

## 5. Сохранение и загрузка данных

- **При запуске**: `load()` читает `weapons.json`. Если файл отсутствует — создаётся пустая коллекция.
- **При выходе**: `save()` автоматически сохраняет коллекцию в `weapons.json`.

Поле `"type"` определяет класс при загрузке:

```json
{
  "type": "Firearms",
  "imia": "AK-47",
  "damage": 85,
  "rare": "Редкое",
  "hardness": 100,
  "effects": "автоматический огонь",
  "tip": "Пушка",
  "kolichestvo": 1,
  "caliber": 7.62,
  "magazine_capacity": 30
}
```

## 8. Вывод

В ходе выполнения лабораторной работы были изучены и применены:

**8.1 Трёхслойная архитектура**
Разделение на CLI, бизнес-логику и модели позволяет изменять каждый слой независимо. CLI не знает о деталях создания объектов — это обязанность `app.py`.

**8.2 Паттерн «Стратегия»**
Стратегии сортировки и улучшения реализованы как функции и callable-объекты. Добавление новой стратегии не требует изменения существующего кода.

**8.3 Фабрики функций**
`make_damage_filter` и `make_rarity_filter` создают предикаты на лету с замыканием над параметрами — гибкий способ параметризации фильтрации.

**8.4 Собственные исключения**
`DuplicateItemError` и `ItemNotFoundError` делают обработку ошибок явной и читаемой, в отличие от встроенных исключений.

**8.5 JSON-персистентность**
Автоматическая загрузка при старте и сохранение при выходе обеспечивают сохранность данных между сессиями без участия пользователя.

Вывод: трёхслойная архитектура в сочетании с паттерном «Стратегия» и фабриками функций обеспечивает гибкую, расширяемую систему, где каждый компонент отвечает только за свои обязанности.
