Лабораторная работа №8: CLI для управления инвентарём оружия
1. Цель работы
Целью данной лабораторной работы является реализация консольного интерактивного приложения (CLI) для управления коллекцией оружия.

В ходе работы были применены следующие навыки и технологии:

Трёхслойная архитектура (CLI → App → Models)

Паттерн «Стратегия» для сортировки и улучшения оружия

Фабрики функций для фильтрации

Собственные исключения для предметной области

Сохранение и загрузка данных в формате JSON

Типизация (аннотации типов) и документация (docstring)

Обработка ошибок пользовательского ввода

Оценка: 5 — реализованы все требования на 3, 4 и 5 баллов.

2. Структура проекта
Проект состоит из следующих файлов:

Исходные файлы студента (не изменялись):

models.py — классы предметной области (Weapon, Firearms, Edged, Inventory)

interfaces.py — интерфейсы Printable, Repairable, Comparable

validate.py — валидаторы атрибутов оружия

strategies.py — стратегии сортировки, фильтры, фабрики функций

generic.py — generic-коллекция TypedCollection

Новые файлы, созданные для лабораторной работы:

exceptions.py — собственные исключения (DuplicateItemError, ItemNotFoundError)

storage.py — функции для сохранения и загрузки данных в JSON

app.py — бизнес-логика (слой между CLI и коллекцией)

cli.py — консольный интерфейс (только ввод и вывод)

main.py — точка входа, авто-загрузка при старте и сохранение при выходе

weapons.json — файл с данными (создаётся автоматически)

README.md — документация

Назначение каждого слоя:

models.py — отвечает за хранение данных и базовую логику оружия

interfaces.py — определяет протоколы для различных операций

strategies.py — реализует паттерн «Стратегия» для сортировки и фильтрации

exceptions.py — определяет собственные типы ошибок для предметной области

storage.py — управляет чтением и записью данных в файл

app.py — содержит бизнес-логику: добавление, удаление, поиск, сортировка

cli.py — отвечает только за взаимодействие с пользователем (меню, ввод, вывод)

main.py — запускает приложение, загружает данные и передаёт управление CLI

3. Описание CLI
Главное меню
При запуске приложения пользователь видит главное меню с 10 пунктами:

Пункт 1 — Добавить оружие
Позволяет добавить новое оружие в коллекцию. Сначала выбирается тип оружия: обычное, огнестрельное или холодное. Затем пользователь вводит все характеристики: название, урон, редкость, прочность, эффекты, тип оружия, количество обладателей. Для огнестрельного оружия дополнительно запрашиваются калибр и ёмкость магазина. Для холодного — длина клинка и материал. При попытке добавить оружие с уже существующим именем выбрасывается исключение DuplicateItemError, и добавление не происходит.

Пункт 2 — Показать всё оружие
Выводит всю коллекцию в виде форматированной таблицы. Таблица содержит столбцы: название, тип, урон, прочность, редкость и дополнительную информацию (калибр/материал). Сломанное оружие отмечается специальным значком.

Пункт 3 — Найти оружие по названию
Пользователь вводит название оружия. Если оружие найдено, выводится полная информация о нём, включая метод get_info() из интерфейса Printable (если реализован). Если оружие не найдено, выбрасывается исключение ItemNotFoundError, и выводится сообщение об ошибке.

Пункт 4 — Удалить оружие
Пользователь вводит название оружия для удаления. Система показывает информацию об оружии и запрашивает подтверждение в формате «Удалить 'Название'? (y/n)». Только после ввода 'y' оружие удаляется из коллекции. Это реализует требование подтверждения опасных операций.

Пункт 5 — Сортировка (стратегии)
Открывает подменю с выбором стратегии сортировки:

По имени (by_name) — в алфавитном порядке

По урону (by_damage) — от большего к меньшему

По редкости (by_rarity) — легендарное > редкое > обычное

По урону, затем по имени (by_damage_then_name) — сначала урон, при равном уроне — имя

По цене (by_price) — по вычисляемой цене оружия

После выбора стратегии коллекция сортируется и выводится в отсортированном виде.

Пункт 6 — Фильтрация
Открывает подменю с 7 вариантами фильтрации:

Только легендарное оружие

Только с высоким уроном (100 и более)

Требует ремонта (прочность меньше 100)

Только огнестрельное

Только холодное оружие

Фильтр по диапазону урона (фабрика функций) — пользователь задаёт минимальный и максимальный урон

Фильтр по редкости (фабрика функций) — выбор конкретной редкости

Фильтрация использует фабрики функций make_damage_filter и make_rarity_filter, которые создают предикаты на лету.

Пункт 7 — Показать сломанное оружие
Выводит только те экземпляры оружия, у которых прочность (hardness) равна 0.

Пункт 8 — Починить оружие
Пользователь вводит название оружия. Если оружие найдено, вызывается метод repair() (или repair_weapon() для классов, реализующих интерфейс Repairable). Прочность оружия восстанавливается до 100.

Пункт 9 — Улучшить оружие
Открывает подменю со стратегиями улучшения:

Повысить урон (+50) — класс DamageUpgradeStrategy

Повысить редкость — класс RarityUpgradeStrategy (обычное → редкое → легендарное)

Полный ремонт — класс RepairStrategy

Это демонстрирует паттерн «Стратегия» через callable-объекты.

Пункт 0 — Выход и сохранение
Завершает работу программы. Перед выходом автоматически сохраняет текущую коллекцию в файл weapons.json.

Обработка ошибок ввода
Приложение обрабатывает следующие ошибки:

Неверный пункт меню — если пользователь вводит число вне диапазона 0-9, выводится сообщение «Неверный пункт меню»

Ввод строки вместо числа — при использовании int(input()) возникает ValueError, который перехватывается, и выводится сообщение «Ошибка: введите число»

Пустые названия — если пользователь ничего не вводит или вводит только пробелы, выводится сообщение об ошибке

Некорректный диапазон — например, прочность не в диапазоне 0-100 — ловится валидаторами в моделях

Сохранение и загрузка (для оценки 5)
При запуске программы — функция load() пытается прочитать файл weapons.json. Если файл существует, данные загружаются в коллекцию. Если файла нет, создаётся пустая коллекция.

При выходе из программы — функция save() сохраняет текущую коллекцию в файл weapons.json в формате JSON.

Формат JSON — каждый объект оружия сохраняется как словарь с полями. Для разных типов оружия (обычное, огнестрельное, холодное) сохраняются разные наборы полей. Поле "type" позволяет при загрузке определить, какой класс создавать.

Подтверждение опасных операций
При удалении оружия программа запрашивает подтверждение:

Удалить 'Экскалибур'? (y/n):

Оружие удаляется только после ввода символа 'y'. Любой другой ввод (например, 'n' или просто Enter) отменяет удаление.
